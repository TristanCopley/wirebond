# wirebond 2.0: the build

> **Historical.** This was the hand-off for wave 2 of the 2.0 build: a skeleton, the interfaces the builders agreed to work against, and who owned which file. Wave 2 is done: every interface below is implemented, and [NOTES.md](../NOTES.md) says where the build stands. It is kept for three things: what 2.0 removed and renamed from 1.x (State), the division of the code that the `Owner:` lines in file headers refer to (Ownership), and what is still open from the hand-off (Still open). Where a signature below and the code differ, the code and its doc comments are right.

SPEC.md is the specification. The builders were told to read SPEC §3, §4, §10.3, §13, §14, §16, §19, §20, §22.4 and §25 first.

## State

When this was written the daemon's pumps, control channels and bond lifecycle and every platform function were stubs behind `#[allow(dead_code)]`, and 52 tests were ignored for wave 2. All of that is written now, the allows are gone, and 11 `#[ignore]` attributes remain (`grep -rn '#\[ignore' crates` lists them with their reasons). What the skeleton changed from 1.x still holds:

- **Removed (§25):** port forwards, serve lists, the Moonlight port preset, TCP splices and fallback flows (`node/fwd.rs`, 1.x's `node/ctl.rs` (2.0 has a new file of that name for its control channels), 1.x `node/status.rs`, the 1.x node and CLI tests, `tests/node`); stable's fits learning and trial threshold; the constants FITS_HOLD, FITS_MARGIN, TRIAL_PASS, MAX_SPLICES, FALLBACK_HOLD, FALLBACK_AFTER, MESH_MTU, SESSION_LINGER, REDIAL_WAITING, REDIAL_MISMATCH, NO_TRAFFIC_AFTER, NEWER_PEER_CHECK, PENDING_COPIES, COPY_LOAD_MAX, FLOW_LANES (the last three are now private to the module that uses them); OUTLINE.md, notes/{core,node,host,update,netsim,cmd,tooling}.md, every SKELETON.md and design/. The one 1.x test of removed behaviour that was deleted outright: `rate::tests::adjust_learns_fits_from_clean_bulk` (fits ≥ X learning is gone).
- **Renamed:** modes are `Performance` and `Bandwidth` (JSON `"performance"`, `"bandwidth"`, nothing else parses); `cheap`/`CHEAP_*` → `small`/`SMALL_*`; `COMBINE_*` → `BANDWIDTH_*`; `capacity.rs` → `bandwidth.rs`; `Role::Server` → `Role::Anchor`; `SESSION_BYTES` → `BOND_BYTES`; `MAX_SESSIONS` → `MAX_BONDS`; `TAILSCALE_ONLY_AFTER` → `MESH_ONLY_AFTER`; `MAX_DATAGRAM` → `MAX_INNER`.

## Interfaces

As agreed when wave 2 began. The code has moved on in places: `Cmd` gained `Install`, `bond open` gained `measure` (pick's temporary bond), `wirebond_core::compat` and netsim's `sim::inner` and `sim::outer` are gone with the 1.x tests they served, and the daemon's `host_failed` reports a missing tool from the error's kind, so host's `missing_tool` and `missing_tools` were removed unused.

### Engine: `crates/core` (wirebond-core)

Pure (§4.2). `crates/core/src/lib.rs` is the public API.

```rust
pub type Mono = i64;                                  // ns, monotonic, caller-supplied
pub enum Role { Client, Anchor }
pub enum Mode { Performance, Bandwidth }              // core::session; serde lowercase; Default = Performance
impl Mode { pub const fn as_str(self) -> &'static str; pub fn parse(s: &str) -> Option<Mode> }
pub const MODE_PERFORMANCE: &str; pub const MODE_BANDWIDTH: &str; pub const PROTOCOL: u32 = 2;
pub struct FlowId(pub u16);                           // a flow number on the wire, per bond and direction

impl Session {
    pub fn new(role: Role, owner: u64, rand: Rand) -> Session;
    pub fn handle(&mut self, now: Mono, ev: Event<'_>, rids: &mut RidTable, out: &mut dyn Out);
    pub fn send_packet(&mut self, now: Mono, packet: &[u8], rids: &mut RidTable, out: &mut dyn Out); // = handle(Event::Send)
    pub fn next(&self) -> Mono;                       // ask after every handle
    pub fn snapshot(&self) -> SessionStatus;
    pub fn close(&mut self, rids: &mut RidTable);
}
pub enum Event<'a> {
    Send { packet: &'a [u8] },                        // one whole IPv4/IPv6 packet read from the TUN device
    Packet { sock: SockId, from: SocketAddr, data: &'a [u8] }, // a lane datagram (STUN already set aside)
    Links { links: &'a [Link], mesh: Option<MeshLane> },
    Wake, Control(&'a Msg), Tick,
}
pub trait Out {
    fn send(&mut self, sock: SockId, to: SocketAddr, data: &[u8]);
    fn deliver(&mut self, packet: &[u8]);             // one whole inner IP packet for the TUN device
    fn control(&mut self, msg: Msg);
}
pub fn packet_rid(b: &[u8]) -> Option<u16>;           // pick the session before handle
pub mod flow { pub struct Key { pub proto: u8, pub src: IpAddr, pub dst: IpAddr, pub sport: u16, pub dport: u16 }
               impl Key { pub fn parse(p: &[u8]) -> Option<Key> } }
pub struct LaneStatus { …, pub first_arrivals: u64, pub rescues: u64, pub reorder_wait_p50: Mono, pub reorder_wait_p99: Mono }
pub struct FlowStatus { pub flow: FlowId, pub tx: bool, pub key: Option<flow::Key>, pub class: &'static str, … }
pub mod b64;                                          // serde `with` for the control protocol's key
```

Invariants:
- A data payload is flow (2) + seq (4) + one inner packet (§10.3): `DATA_LEN` 6, `OVERHEAD` 33, `MAX_INNER` = 1500 − 33. A packet that does not parse as IP or is longer than `MAX_INNER` is dropped.
- The session keys flows itself (§13): a flow I send is found by `flow::Key` and numbered by me from 1; a flow I receive is found by the peer's number. Directions never share a slot. At most `MAX_FLOWS` (4096) slots; a new flow beyond that evicts the flow idle longest (`flows_dropped` counts it); a flow idle `FLOW_IDLE` ends on the next tick. There is no `FlowEnd` event any more.
- The daemon, not the engine, checks inner addresses (§10.5 rule 6) and never hands the engine JSON (§4.2): `node/proto.rs` maps `key`, `links`, `mode` and `bond open`'s mode onto `Msg`.
- `crates/core/src/consts.rs` holds exactly §21's constants and the wire's sizes and flags. Tunables the spec does not name are private to their module.
- `wirebond_core::compat` (hidden) maps 1.x's (port, number) flows and bare datagrams onto inner UDP packets for the old tests and benchmark only. Delete it once they are rewritten.

### Control protocol v2: `crates/wirebond/src/node/proto.rs`

```rust
#[serde(tag = "t", rename_all = "snake_case")]
pub enum Msg { Hello(Hello), Error(Error), Bond(Bond), Key(Key), Links(Links), Mode { mode: Mode },
               Support(Support), Measure(Measure), View(View) }
pub struct Hello { pub v: u32, pub inst: u64, pub name: String, pub role: Role, pub version: String }
pub struct Error { pub code: ErrorCode, pub msg: String }  // version not_allowed too_many_bonds busy unknown bad_request
#[serde(tag = "op")] pub enum Bond { Open { mode }, Ok { addr4, addr6, mtu, dns, egress }, Close }
pub struct Key { pub rid: u16, pub key: Vec<u8> /* base64 */, pub epoch: u64, pub floor: u64 }
pub struct Links { pub links: Vec<LinkOffer> }   // LinkOffer { id, kind, metered, group, support, cands }
pub struct Support { pub cable_subnet: String, pub name: String }
#[serde(tag = "op")] pub enum Measure { Start { seconds, bulk_bytes }, Result { lanes: Vec<MeasureLane>, egress_ms } }
pub struct View { pub status: Option<Box<api::Status>> }     // request: no status
pub fn encode(m: &Msg) -> Option<Vec<u8>>;                   // JSON + '\n', None past MAX_MSG
pub fn decode(line: &[u8]) -> Result<Msg, ErrorCode>;        // Unknown for an unknown "t", BadRequest otherwise
```

On the wire: `{"t":"bond","op":"open","mode":"performance"}`. Unknown fields are ignored.

### Platform API: `crates/wirebond/src/host/net.rs`, bodies per OS

```rust
pub struct TunConfig { name, mtu, addr4: Option<(Ipv4Addr, u8)>, addr6: Option<(Ipv6Addr, u8)> }
pub enum Routes { All, BondOnly }
pub struct Capture { tun, routes, bond4, bond6, exclude: Vec<(IpAddr, u8)>, links: Vec<String>, dns: Option<IpAddr> }
pub struct Egress { tun, net4, net6 }   pub struct EgressOn { v4, v6, addr4 /* 192.168.137.1/24 from Windows ICS */, uplink }

// per OS (linux.rs, macos.rs, windows.rs), re-exported by host/mod.rs:
Tun::open(&TunConfig) -> io::Result<Tun>; Tun::name(&self) -> &str;
Tun::read(&self, &mut [u8]) -> io::Result<usize> /* WouldBlock when empty */; Tun::write(&self, &[u8]) -> io::Result<()>;
unix: impl AsRawFd for Tun, Poll::add_tun(&mut self, &Tun);   windows: Tun::read_event(&self) -> HANDLE
capture_install(&Capture) / capture_remove(&Capture) -> io::Result<()>
egress_enable(&Egress) -> io::Result<EgressOn>; egress_disable(&Egress) -> io::Result<()>
upstream_resolver() -> io::Result<SocketAddr>
support_share(&Share) / support_unshare(&Share) -> io::Result<()>
cleanup_stale() -> io::Result<()>                      // the daemon calls it first at start (§5.4)
```

When this was written every body returned `io::ErrorKind::Unsupported` with `NOT_YET`; all are written for Linux, macOS and Windows now. Every function is idempotent and undoes only what wirebond made. Lane sockets: `host::listen` pins them; on Linux it now also sets `SO_MARK 0x7849` (ignored without CAP_NET_ADMIN). What 1.x had and works stays: link listing, `listen`/`listen_mesh`, `Poll`, `Waker`, `Wake`, local sockets, `install`/`uninstall`, `run_service`, the updater's hooks.

### CLI: `crates/wirebond/src/cli/mod.rs`

`pub fn parse(args: &[String]) -> Result<(Cmd, bool /* --json */), String>` with `pub enum Cmd { Api(Request), Version, Uninstall, Run, Help }`; exit codes `OK 0, FAILED 1, USAGE 2, NO_DAEMON 3, NEEDS_ADMIN 4, REFUSED 5` (§19), mapped from `ApiError::code`. A changing verb with no daemon installs the service when admin.

### Daemon: `crates/wirebond/src/node/mod.rs`

`pub fn run(version: &str, stop: Receiver<()>) -> io::Result<()>`: config, `cleanup_stale`, the local API (one accept thread per socket, the loop answers), then one loop: `poll.wait(min(engine deadlines, next scan, 500 ms))`, then `tun_pump`, `lane_pump`, local API calls and `tick` (stubs then, written since). The config-changing verbs save config.json, and status is §20.2's.

### netsim seam: `crates/netsim/src/sim.rs`

Gone since: netsim now sends real inner IP packets (NOTES.md). As it was: netsim keeps 1.x's application flows as its own `sim::FlowId(u32)` (port ≪ 16 | number) and converts at the engine boundary: `sim::inner(f, data) -> Vec<u8>` (IPv4/UDP from 10.77.0.2:number to 10.77.0.1:port, `INNER_HDR` 28 bytes) and `sim::outer(packet) -> Option<(FlowId, &[u8])>`. `node.rs` keeps 1.x's MESH_MTU, REDIAL_WAITING and SESSION_LINGER as private constants until its port.

## Ownership for wave 2

Historical: the rule that bound the wave-2 builders. The `Owner:` lines in file headers still name these owners.

Each engineer edits only their files. Anything else: ask its owner (below) with the exact change, its signature and why; keep working against the current signature until the owner lands it. No new dependencies (§22.5).

## Still open

What the hand-off listed as open that is still true, checked against the code when this file was marked historical. The spec gaps it listed are in NOTES.md's Open list now, with the ones found since.

- **Core:** `Msg` is still the 1.x-shaped control struct, with serde, in core (§4.2 wants typed events and no JSON in core); the six engine test vectors are not regenerated from Rust (NOTES.md).
- **Host:** the code of 1.x's macOS login agent (`Scope::User`, `made_bin`) survives, to replace an agent with the system service, though §25 removes the agent; Linux IPv4 lane sockets pin with `IP_UNICAST_IF` where §5.3 says `SO_BINDTODEVICE` (linux.rs says why).
- **netsim:** the "primary" and "trial" vocabulary of §25 is still in `check.rs`, `metrics.rs`, `fake.rs` and core comments; `node.rs` keeps 1.x's MESH_MTU, REDIAL_WAITING and SESSION_LINGER as private constants.
- **Comments:** `crates/core` and `crates/netsim` still cite the 1.x specification's section numbers, the Go sources and the deleted 1.x notes (NOTES.md, Not done).

Closed since the hand-off: the contribution statistics and `RESCUE_GAP`; `compat`, the fits fields and all but 11 of the ignored tests; every platform function, the Windows event loop and the daemon's pumps, lifecycle, failure rules, DNS relay, pick and update schedule; netsim's seam and its acceptance baselines; the 1.x README and notes, and Go in CI.
